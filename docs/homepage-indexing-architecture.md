# 主页本地索引架构

## 目标

主页组件只从插件当前本地索引读取展示数据，避免每次渲染都执行全库 SQL。索引不存在时可以创建空索引；需要从当前文档重新生成的索引，必须由用户在“主页设置 → 检索管理”中手动重建。

本架构不读取或迁移旧文档属性。

## 当前索引

| 索引 | 当前来源 | 维护方式 |
| --- | --- | --- |
| 收藏文档 | 当前收藏操作 | 刷新失效文档；用户重新收藏 |
| 复习文档 | 当前复习计划操作 | 刷新失效文档/块；用户新增复习计划 |
| 任务管理 Plus | 当前任务块 | 增量刷新或手动全量重建 |
| 热力图 | 当前文档更新时间 | 增量刷新或手动全量重建 |
| 统计卡片 | 当前文档与块统计 | 增量刷新或手动全量重建 |
| 强化日记 | 带官方 `custom-dailynote-YYYYMMDD` 属性的日记 | 增量刷新或手动全量重建 |
| 强化日记项目/记录 | 当前项目节点和记录 | 增量刷新或手动全量重建 |

## SQL 边界

- 组件展示只读本地索引，不得因为索引为空在后台触发全库 SQL。
- 用户明确点击重建时，才允许执行用户可感知的全量索引 SQL。
- 增量刷新只查询最近变化或已有索引中需要确认的 ID。
- SQL 必须经过当前 checked/manual-index 入口、限制表名和最大结果数量。
- 单个索引失败不得阻止其他索引继续维护，结果分别记录到对应 `*IndexStatus`。

## 文件完整性

- 当前索引必须校验 schema/version 和根结构。
- 损坏索引不得按空索引处理，也不得静默覆盖。
- 写入采用当前 checked API，写后重读校验；目录创建失败可继续尝试当前文件写入，以适配不同思源内核行为。
- 索引版本升级后由当前数据重建，不执行旧格式转换。

## 用户入口

“主页设置 → 检索管理”是唯一索引维护入口，提供：

- 刷新全部索引；
- 重建全部索引；
- 各索引单独刷新或重建；
- 最近一次状态、时间、处理数量和错误信息。

组件空态只引导用户使用当前操作，不再显示“迁移旧属性/旧数据”的入口或提示。
