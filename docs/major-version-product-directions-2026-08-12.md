## 3. 当前开发结论

### 3.1 Agent 主线暂时收口

Agent 平台从 A0 到 A8.6 已形成完整纵向链路。当前不继续增加新的自动化类型或额外 Agent 入口，先在真实使用中验证：

- 定时任务是否准时触发、重启后是否正确补发。
- 本地 AI、QQ、微信、飞书的结果路由是否稳定。
- 新建对话和绑定已有对话的上下文是否符合预期。
- 无人值守工具权限是否既能完成任务，又不会越权执行高风险操作。
- 长对话压缩、检查点恢复、记忆自动学习和临时工作台是否出现回归。

后续遇到问题时按现有架构修复根因，不重新建立第二套调度器、机器人连接、会话存储或 Agent 循环。

### 3.2 当前项：全局日历第一阶段

“高度自定义的全局日历组件”已完成第一版实现，当前等待真实界面验收：

1. 日历是任务、强化日记、纪念日、习惯和专注等时间数据的共同展示基础。
2. 先建立统一事件契约，可以避免后续习惯和番茄钟再次各自实现日历。
3. 第一阶段只做聚合、筛选、主题适配和可靠跳转，范围清楚，能够独立验收。

第一阶段不做拖拽改期、跨来源编辑、复杂日程冲突处理或自然语言排程。这些能力必须等只读事件契约稳定后再决定。

建议提交信息：`新增全局日历聚合任务日记与重要日期。`

## 4. 已完成的基础能力

### 4.1 设置发现与信息架构

- 主页设置支持全局搜索，结果定位到具体设置项，而不是只打开大分类。
- 设置注册元数据声明所属路径、作用域和检索关键词。
- 点击结果后打开对应页面、滚动到目标并高亮。
- 实时保存保持不变；设置页右上角提供轻量保存状态，不用全局消息打断操作。

### 4.2 组件与主题体验契约

主题适配只描述视觉骨架，不把业务功能当成视觉类别。当前呈现类别为：

| 类别            | 主题适配含义                       | 组件示例                            |
| --------------- | ---------------------------------- | ----------------------------------- |
| `collection`    | 重复条目、卡片或时间线组成的内容流 | 最近文档、收藏、任务、最近日记      |
| `metrics`       | 少量关键数字和短标签               | 天气、统计卡片                      |
| `visualization` | 图表、热力图、数据画布或查询结果   | 热力图、SQL、数据库图表             |
| `editorial`     | 阅读、书写或长文本优先             | 自定义文档、便签、每日一句          |
| `media`         | 图片、封面或播放内容主导           | 图片轮播、音乐播放器                |
| `control`       | 单一操作目标明确的交互工具         | 专注计时、倒计时、赛博木鱼          |
| `embedded`      | 外部页面或隔离运行时主导           | 网页浏览器                          |
| `workspace`     | 多区域、多状态的复合工作台         | 固定资产、强化日记、记账、AI 知识库 |
| `intrinsic`     | 自带完整造型，不适合主题强制包卡片 | 仿真时钟、黄历                      |

展示变体只登记会改变视觉骨架的稳定模式，例如自定义文档的标准、紧凑和沉浸，时间日期的经典与仿真表盘。筛选、颜色、排序等业务配置不进入主题变体。

运行时统一暴露呈现类别和展示变体，主题解析顺序为“变体 → 组件覆盖 → 类别 → 通用回退”。新增主题不得继续依赖散落的组件名称选择器。

### 4.3 全局性能优化

已完成启动关键路径分层、非关键能力空闲启动、组件数据有界并发、真实加载进度、共享时钟、隐藏页暂停、重型依赖按需构建和通知调度快照复用。

后续开发继续遵守：

- 首屏只承担必需工作，Agent、图表、富文本和媒体能力延后加载。
- 不可见组件暂停高频刷新，组件销毁必须清理计时器、监听器和 Observer。
- 单个组件失败不能阻塞整页。
- 加载进度由真实阶段驱动，不用假动画模拟。
- ECharts 继续从项目的模块化入口引用，不恢复完整 bundle。

详细记录见 `docs/global-performance-optimization-2026-08-12.md`。

## 5. Agent 平台架构基线

本节是后续所有 AI 功能必须遵守的长期边界，不再为每个功能重复写一套 Agent 方案。

### 5.1 总体目标

知识库对话是全能力入口，但不是其他入口依赖的页面组件。机器人、状态语、划词、主页智能表面和后台任务都通过 Profile 按需装配同一套平台能力。

```text
知识库 / 机器人 / 状态语 / 划词 / 主页 / 后台任务
                         ↓
                Agent Profile 注册表
                         ↓
                  统一运行组装入口
       ┌──────────┬──────────┬──────────┐
       │模型协议  │上下文装配│能力与权限│
       └──────────┴──────────┴──────────┘
                         ↓
               NativeToolAgentLoop
                         ↓
             Run / Step / Event 记录
                         ↓
       UI、机器人消息、恢复、诊断与后台结果
```

任何新入口不得重新实现模型请求、工具循环、上下文压缩、确认、错误恢复、trace 或会话存储。

### 5.2 能力层级

1. **模型生成层**：单轮/流式生成、取消、超时、Provider 适配、错误和用量。
2. **上下文对话层**：多轮会话、上下文预算、摘要和持久化。
3. **工具 Agent 层**：工具选择、参数校验、权限、结果回传和恢复。
4. **知识与记忆层**：知识检索、工作记忆和长期记忆，读写分别授权。
5. **扩展能力层**：MCP、Skills、主页组件、编辑器和领域能力，逐项注册。
6. **自治执行层**：后台 Job、定时、心跳、检查点和运行账本。

轻量入口只使用需要的层级。状态语不因为“统一”而进入完整工具循环，后台任务也不能因为无人值守而自动获得全部工具。

### 5.3 运行身份和事实来源

- `sessionId`：长期会话或后台任务线程。
- `runId`：一次用户提交或一次后台触发。
- `stepId` / `stepIndex`：模型请求或工具步骤。
- `eventId`：文本、工具、审批、错误、检查点和结束事件。
- `correlationId`：串联 UI、Provider、工具、日志和恢复记录。

聊天 UI、执行状态、恢复提示和诊断信息都从统一事件投影，不得各自推断运行状态。模型说“已经完成”也不能替代真实环境的最终状态验证。

### 5.4 Profile 和最小权限

每个入口通过版本化 Profile 声明：

- 模型和输出契约。
- 可用上下文来源。
- 工具与聚合 action 白名单。
- 记忆读取和写入权限。
- Skills 与 MCP 范围。
- 最大步骤、超时、成本和后台限制。
- 写操作确认、远程限制和失败恢复策略。

最终权限取平台硬限制、Profile、用户设置、运行环境和单次授权的交集。未授权能力不能进入工具清单、系统提示或真实执行入口，也不能通过聚合工具绕过。

### 5.5 上下文与安全恢复

上下文使用五层结构：

1. 不可压缩约束和当前任务目标。
2. 当前工作状态、待完成步骤和可靠工具结果。
3. 最近若干轮完整原文。
4. 带覆盖范围的分层摘要。
5. 旧对话、原始工具结果和文档的按需检索引用。

每次请求生成 Context Manifest，记录注入来源、字符/token、排除原因和摘要覆盖范围。写操作结果未知时必须先回读，不能盲目重放；只有安全检查点允许恢复。

## 6. Agent 高级能力 A8

### 6.1 A8.1 主页能力注册｜已完成

- `AgentContextProvider` 和 `AgentActionProvider` 统一声明主页/组件作用域、敏感等级、真实工具/action、读写属性和确认要求。
- 能力快照只来自本轮真实注册且经过 Profile 过滤的工具。
- 组件复用现有知识库、日记、数据库和业务工具，不复制读取或写入实现。
- 新的主页 Agent 表面只消费能力快照，不在组件内部创建 Agent 循环。

### 6.2 A8.2 临时智能工作台｜已完成

产品定位：Agent 使用本轮真实工具结果生成临时信息工作台，而不是在回答中堆一大段表格。

当前实现：

- AI 可组合白名单语义标签和内置 `wb-*` 视觉类，不受少量固定模板限制。
- HTML 在工具边界清理；脚本、事件、任意样式、外链、表单和非法思源 ID 均被拒绝。
- 首期只允许打开思源文档或块，不把写操作藏进 HTML。
- 完整工作台保存在 `notebrain/workbenches/`，各入口只保留 ID 引用。
- 聊天回答只显示“打开工作台”入口，完整内容用项目统一弹窗容器展示。
- “AI 知识库 → 临时工作台”统一管理来源、引用和空间占用。
- 该能力属于 Agent 平台扩展，可被本地聊天、机器人、主页或后台任务按 Profile 注册，不与知识库聊天组件绑定。

`A8.3 工作台调整与固定` 已跳过。临时工作台当前不固定为主页正式组件，也不继续开放通用写动作。

### 6.3 A8.4 全局记忆与记忆中枢｜观察中

产品目标：让不同 Agent 入口共享一套会随用户使用而进化的长期记忆，而不是把某个思源文档全文塞进每轮上下文。

当前实现：

- 旧版“单一思源文档即全局记忆”设置和调用已停用；不迁移也不删除用户原文档。
- 新数据保存在插件本地多文件 JSON：`profile.json` 保存开关，`index.json` 保存轻量索引，`items/{id}.json` 保存单条记忆。
- 记忆支持身份、偏好、目标、约束、项目、关系、决定和经历类型，并记录重要度、置信度、强化次数、来源和时间。
- `memory_manage` 提供搜索、记住、更新和遗忘；Agent 只看到语义 ID，不知道文件路径。
- 开启“允许 AI 自动学习”后，低风险记忆操作无需逐次确认；关闭后写入继续要求确认。
- 每轮只注入少量相关记忆和置顶事实，不把整库常驻上下文。
- 知识库与机器人共享同一记忆；状态语只读；划词入口保持局部无状态。
- “AI 知识库 → 记忆中枢”支持总开关、搜索、筛选、编辑、置顶和永久删除。

禁止保存临时请求、工具输出、助手猜测、第三方事实、密码、令牌、验证码和高敏感人格推断。当前先观察召回准确性、错误记忆、冲突修正和长期膨胀问题。

### 6.4 A8.5 LLM Wiki｜取消

本次大版本不创建 Wiki 数据库、向量索引、Embedding 配置、后台索引 Job 或迁移层。原因是跨桌面、Docker、浏览器和移动端的数据库与模型生命周期仍过重，不适合作为当前插件发布前置条件。

未来只有在以下条件同时满足时重新立项：

- 插件和 Agent 平台经过多个版本稳定使用。
- 思源 Kernel 插件或统一后台服务能可靠运行跨端索引。
- 数据存储、备份、模型切换和 Embedding 重建成本有明确方案。
- 真实用户需求足以覆盖长期维护成本。

### 6.5 A8.6 Agent 自动化中心｜观察中

#### 产品边界

自动化中心只管理“到点或发生变化后运行 Agent”的任务；通知中心只管理“到点投递既定内容”的通知规则。

```text
自然语言 / 设置页
        ↓
版本化 Job Definition
        ↓
Scheduler（到期、补发、幂等）
        ↓
Sensor（心跳任务才有；无变化不调模型）
        ↓
Background Agent Profile
        ↓
Run Ledger
        ↓
运行记录 / 本地 AI 会话 / 机器人会话
```

#### 当前能力

- 支持一次、每日、每周、每月、固定间隔和心跳传感器任务。
- Job、可变状态和运行记录分片保存在 `notebrain/agent-automation/`。
- 任务支持暂停、编辑、复制、删除和“运行一次”；新增/编辑使用统一弹窗，不常驻占用设置页面。
- 结果可只保留运行记录，也可发送到本地 AI 或机器人。
- 本地 AI 和机器人都支持每次新建对话或绑定已有对话；已有会话可搜索并按最近时间排序。
- 机器人会话只显示当前默认/活跃 Provider 对应的 QQ、微信或飞书会话，不混用渠道路由。
- 后台 Agent 继承目标入口已经配置的工具权限，不再硬编码少量只读范围。
- 无人值守执行仍受安全策略约束：低风险、可审计动作可自动运行；高风险、不可逆或结果未知的动作不能绕过保护。
- 同一时间槽使用幂等键防止重复运行；上一轮未完成时不并发启动同一任务。
- Runner 离线后按补发策略跳过或只补最新一次，不批量回放所有错过任务。
- 运行记录有界保存，不记录 API Key、完整文档正文、本地绝对路径或不必要的推理内容。

#### 跨端边界

| 运行位置             | 可以承担                                    | 不承诺                             |
| -------------------- | ------------------------------------------- | ---------------------------------- |
| 桌面端/Electron      | 应用运行期间的 Agent、桌面能力、QQ/飞书出站 | 应用完全退出后继续执行             |
| Kernel/Docker Runner | Kernel-safe Agent、Sensor、微信或外联出站   | 调用浏览器 DOM 或桌面专属工具      |
| 移动端               | 管理任务、查看结果、接收提前注册的固定通知  | App 被系统挂起后持续运行完整 Agent |
| 普通浏览器           | 页面打开期间管理和执行安全任务              | 关闭标签页后继续计时               |

动态 Agent 任务必须有在线 Runner。没有云端服务且所有 Runner 都离线时，不能伪装成仍可准时运行。

#### 后续处理方式

当前版本已经满足定时 Agent 的基本使用，进入观察期。暂不新增原始 cron、任意脚本、复杂规则编排、多 Runner 自动抢占或无限后台权限。后续只根据真实故障修复调度、结果路由、权限和恢复链路。

## 7. 下一阶段功能规格

### 7.1 高度自定义的全局日历｜进行中

#### 产品定位

主页缺少跨业务模块的统一日历。它不是强化日记日历的复制品，而是所有时间型信息的聚合视图和操作入口。

#### 第一阶段数据源

- 强化日记：日记存在状态、计划、复盘和快速记录。
- 任务与任务管理 Plus：开始、截止、完成和延期。
- 纪念日、倒计时和已有提醒数据。
- 习惯与番茄钟先预留 Provider 注册能力，等对应功能建成后接入。

#### 统一事件契约

各模块通过 `CalendarEventProvider` 注册事件，日历组件不能直接读取每个业务文件。标准事件至少包含：

- 稳定事件 ID、来源模块和来源对象 ID。
- 标题、开始/结束时间、全天/跨日属性和时区。
- 类型、颜色语义、图标和显示优先级。
- 只读/可写能力、详情动作和跳转目标。
- 可选项目、标签和状态字段，用于筛选。

#### 第一阶段展示

- 主页自适应月视图、详细月视图和日程列表。
- 按来源筛选；组件保存来源、周起始日、相邻月份、数量、预览密度和详细页默认视图。
- 小尺寸只展示摘要点、数量和主要事件；放大后逐步展开详情。
- 主题通过 `visualization` 呈现类别统一适配，组件内部只使用主题 token。
- 点击事件打开详情或跳转来源；只读事件不显示编辑能力。

#### 第一阶段验收

- 单一数据源失败不影响其他来源和整个主页。
- 跨日、全天、时区和同一日大量事件的显示稳定。
- 月历/日程切换后筛选条件不丢失。
- 组件缩放、主题切换和移动端窄屏布局正确。
- 不重复维护任务、日记或纪念日数据，只保存日历组件自身配置。

拖拽改期、快速新增、跨来源编辑、自然语言排程和复杂冲突检测不在第一阶段。

### 7.2 习惯打卡系统与主页组件｜待开发

习惯不是重复任务，需要独立模型：

- 计划支持每天、指定星期、每月次数、周期次数和自定义间隔。
- 打卡支持完成/未完成、次数、时长、数值和等级。
- 记录区分完成、部分完成、跳过、未完成和补签。
- 主页提供今日打卡、周期进度和连续记录；完整习惯中心提供月历与趋势。
- 与全局日历、强化日记和番茄钟共享同一习惯服务。
- Agent 可以查询趋势和建议调整，但不能擅自补签或修改历史。

### 7.3 高级番茄钟与专注数据中心｜待开发

升级现有专注会话，不建立第二套记录：

- 开始专注时可绑定任务、项目或习惯，历史以稳定 ID 为准。
- 支持自定义专注/休息循环、暂停、提前完成、取消和中断原因。
- 任务详情展示累计专注时长、次数和最近专注。
- 数据中心提供日/周/月/年统计、任务/项目/习惯分组、热力图、时段分布和趋势。
- 主页组件只保留当前计时、今日摘要和快速开始。

### 7.4 强化日记工作台底层承载｜明确保留

晨间计划、晚间复盘和周期回顾继续由强化日记工作台完成；主页只显示摘要、进度、提醒和入口。

后续需要抽取无界面的领域服务和摘要 ViewModel，供完整工作台、主页组件、全局日历和 Agent 共用。主页不得通过隐藏挂载完整工作台来读取状态，也不得维护第二份数据。

## 8. 后续逐步推进

### 8.1 数据库数据转图表组件

项目已有隐藏基础。重新开放前应把“数据源 → 字段映射 → 聚合转换 → 图表呈现”拆开：

- 选择思源数据库及分类、数值和日期字段。
- 支持计数、求和、平均、最大/最小和时间分组。
- 支持折线、条形、饼图、排序、筛选、空值和 Top N。
- 点击图表可定位来源行或文档。
- 图表颜色、字体和交互接入主题 token。
- 大数据先在服务层聚合，不把全部原始行直接交给 ECharts。

### 8.2 文献阅读数据组件与思源同步

实现前先确认目标是 Zotero 还是其他软件及其正式接口。首期定位是独立数据组件，不是 Agent MCP：

- 展示文献、集合、分类、最近阅读、批注和笔记统计。
- 建立外部文献 ID 与思源文档 ID 的稳定映射。
- 第一阶段只做外部文献库到思源的单向增量同步。
- 提供同步预览、冲突提示、失败重试和记录。
- 后续可把只读查询注册给 Agent，但不能成为组件可用的前提。

### 8.3 内容对象右键动作

- 按组件对象模型逐步接入，不一次覆盖全部组件。
- 第一批候选：最近文档、收藏、任务、任务管理 Plus、最近日记和复习文档。
- 动作由业务模块注册，例如打开、收藏、加入今日计划、开始专注、交给 Agent和复制链接。
- 普通右键优先内容对象；`Alt + 右键`继续强制打开组件菜单。
- 自定义文档和便签编辑区继续尊重编辑器自身右键。

## 10. 尚待确认的组件高级化候选

这些方向不进入当前开发队列，不能挤占全局日历、习惯和番茄钟：

- **复习文档 → 复习中心**：每日队列、逾期积压、记忆结果和保留率。

## 11. 从现在开始的实施顺序

1. **验收全局日历第一版**：检查不同组件尺寸、主题、移动端和数据跳转。
2. **习惯打卡**：验收通过后先建领域模型和今日打卡，再接入日历与强化日记。
3. **高级番茄钟**：扩展现有专注记录，完成任务/项目/习惯绑定和数据中心。
4. **数据库图表**：重构已有隐藏实现并重新开放。
5. **文献数据组件**：确认接口后实现独立服务和单向思源同步。
6. **内容对象动作**：按组件逐步接入。

Agent 自动化、记忆和临时工作台现在进入真实使用观察期，不占用下一项功能开发顺序；出现问题时作为现有功能缺陷修复。
