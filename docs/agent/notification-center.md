# 通知中心开发规则

## 适用范围

修改系统通知、移动通知、Webhook、飞书、通知历史、通知规则或移动计划时读取本文件；当前文件清单和业务接入契约均在本文件记录。

## 统一边界

- 业务模块只决定“为什么通知、通知什么”、条件、正文、时间、目标和业务数据错误隔离；`notification-center` 是唯一投递基础设施，负责通道、历史、发生实例/投递去重、限流、设备判断、移动计划和权限校验。
- 业务不得直接调用 Notification API、`platformUtils.sendNotification`、Webhook/飞书接口，也不得建立第二套历史、去重、限流、移动计划或调度器。通知失败只产生可解释的投递结果，不回滚已完成业务。
- `new Notification(...)`、思源移动通知 API 和远程通道请求只能出现在 `notification-center` 的通道实现中；业务统一通过 `notificationCenter.notify` 接入。
- 桌面系统通知、移动通知、移动计划、Webhook、飞书和通知配置属于 VIP 能力；VIP 校验必须同时存在于配置保存边界和实际调用边界，隐藏 UI 不能替代权限控制。免费用户仍保留普通 `showMessage` 和原有笔记内会员提示，它们不属于统一通知中心。
- 会员失效时保留通知设置、业务规则和通知历史；当前设备计划进入撤销流程，单条取消失败要保留记录和错误，不得影响其他计划。会员恢复后按原设置和业务数据重新对账并恢复当前设备计划。

## 数据可靠性

- 通知中心设置、通知历史和移动计划是独立数据域。确认文件不存在才可返回默认关闭设置/空文件；读取失败、真实空文件、非法 JSON、schema/version 错误或设备不匹配必须报错，不得静默覆盖或解释为空。
- 一个 Provider、规则或单条计划取消失败不能阻止其他项；失败记录和已有计划必须保留，以便解释和重试。
- 移动计划替换按“注册新通知 → 保存新 `notificationId` 并回读验证 → 取消旧通知”，同一设备串行执行，不能先删除旧计划。移动计划只在移动运行环境读取和维护，桌面端/普通浏览器不创建或校验移动计划文件。
- 动态摘要依赖通知时刻附近的最新业务状态，不能把旧快照长期固化为移动计划，也不能为了提前计划新增全库扫描。
- Provider 失败时保留该来源已有计划；单条规则失败不能阻止同模块后续规则，失败规则不能写成功历史；取消失败继续保留可重试记录。普通对账和强制重建不得并行写入，同一轮要处理合并后的尾随请求。
- 强化日记的日记、任务、项目数据分别加载；一域失败不能阻止其他提醒，也不能把读取失败解释为对象不存在或规则已满足。

## 当前业务接入

- 通用任务通知只有一个配置文件 `taskNotifySettings.json`、执行模块 `task-notify`、调度器 `taskNotifyScheduler` 和移动 Provider `taskMobileNotificationPlanProvider`；任务管理 Plus 与移动任务组件不提供第二套入口、调度器或 Provider。
- 强化日记面板分为通用任务、日记与复盘、任务整理、项目进展、数据维护。通用任务仍管理 `taskNotifySettings.json`，其余专属通知管理 `enhancedDiaryNotifySettings.json`；两个文件独立加载、保存和报错，不能互相用默认值覆盖异常内容。
- 项目通知属于强化日记工作台，不建立 `project-notify`、`projectNotifySettings.json`、独立项目调度器或独立项目移动 Provider。纪念日、复习文档和番茄钟分别继续由 `countdown-notify`、`review-notify`、`focus-notify` 接入统一中心；AI/MCP/Agent 当前不接入通知。

固定时间提醒在当前设备、VIP 状态、移动设置和规划范围均有效时可以提前注册：任务固定提醒、纪念日、复习到期、强化日记固定周/月/年复盘。今日任务动态摘要、项目风险/停滞/周进展、任务整理和实时日记状态属于动态摘要，不能提前固化。

计划替换必须先注册新计划、保存并回读新 `notificationId`，最后取消旧计划；任一步失败都以保留旧计划、防止漏提醒为优先，不得先删旧记录。移动计划改动按设备串行执行，且只在移动运行环境维护。

## 规则与数据文件

强化日记通知规则包括：

- 通用任务：指定时间、今日/明日/逾期/高优先级/自定义筛选摘要，继续复用 `task-notify` 的规则类型、字段、筛选、正文、调度和移动计划。
- 日记与复盘：今日日记未创建、昨日未复盘、日/周/月/年度复盘。
- 任务整理：未迁移任务、工作台逾期任务、长期未处理任务。
- 项目进展：项目逾期风险、长期停滞、完成待归档、项目周进展。
- 数据维护：模板缺失、项目关系异常、项目索引异常；优先留在强化日记面板解释和处理，不拆出项目通知模块。

所有规则复用已有业务数据，不复制业务数据。昨日复盘的 `completed`、`skipped` 不提醒，`pending`、`missing_template` 提醒；检查未知、Markdown 读取失败或读取抛错不误报、不写成功历史。

当前文件清单：

| 数据域 | 文件 | 说明 |
| --- | --- | --- |
| 通知中心设置 | `notification-center/settings.json` | 桌面、移动、Webhook、飞书设置 |
| 通知历史索引 | `notification-center/history-index.json` | 年度历史文件索引 |
| 通知历史 | `notification-center/history-YYYY.json` | 年度投递历史 |
| 移动计划 | `notification-center/mobile-plans/<device-id>.json` | 当前设备计划和 `notificationId` |
| 任务通知 | `taskNotifySettings.json` | 通用任务通知唯一配置 |
| 纪念日通知 | `countdownNotifySettings.json` | 纪念日规则 |
| 强化日记通知 | `enhancedDiaryNotifySettings.json` | 日记、复盘、整理、项目进展 |
| 复习通知 | `reviewNotifySettings.json` | 复习文档通知 |
| 番茄钟通知 | `focusNotifySettings.json` | 番茄钟通知 |

上述文件只接受当前 schema/version；版本升级通过当前数据重新配置或重建，不读取旧格式，读取异常不得静默覆盖。

## 日期与去重

- 所有业务日期使用本地年月日，禁止用 `toISOString().slice(0, 10)` 代替本地业务日期。
- 运行时通知与移动计划对同一业务实例复用相同的 `occurrenceKey`、周期范围和稳定 `planKey`；同一规则、同一周期只能生成一个计划。
- 复盘周期固定为：月末对应当前月，次月首日对应上一月；年末对应当前年度，次年首日对应上一年度。

通知改动只验证通知链路，不因它自动运行无关的 Agent、主题或索引检查；当前实现以 `src/features/notification-center/` 和设置页通知组件为准。
